# sssd Role

Connects Linux hosts to the Authentik LDAP Outpost for NSS/PAM lookups,
password authentication, and SSH public keys. This implements stage 6 of
`docs/plans/identity-authentication-architecture.md`.

```text
Linux host -> NSS/PAM -> SSSD -> LDAPS -> Authentik LDAP Outpost
```

## Functionality

- Creates the passwordless-sudo break-glass account before LDAP integration.
- Installs SSSD, NSS/PAM integration, LDAP tools, and the Authentik LDAP
  certificate.
- Deploys `/etc/sssd/sssd.conf` with mode `0600` and enables
  `pam_mkhomedir`.
- Retrieves SSH keys from Authentik through `sss_ssh_authorizedkeys`.
- Allows active members of `sssd_allowed_login_group` to log in.
- Grants password-protected sudo to `sssd_sudo_group` through a managed
  sudoers file.

The LDAP certificate is the `homelab-ldap` certificate generated by the
`authentik` role for `ldap.home.butaco.net`. Authentik's built-in certificate
has a random `*.self-signed.goauthentik.io` SAN and cannot validate that name.

## Authentik schema

Authentik's LDAP Outpost differs from stock RFC2307:

- Login names use `cn`; `uid` contains an opaque identifier.
- Users, groups, and per-user virtual groups live under `ou=users`,
  `ou=groups`, and `ou=virtual-groups` respectively.
- Objects use `user` and `group`, requiring `rfc2307bis` and explicit object
  classes.
- Authentik assigns `uidNumber` and `gidNumber` from the provider ranges,
  starting at 10000.

## Variables

### Secret

`sssd_ldap_bind_password` lives in
`inventories/homelab/group_vars/sssd.sops.yaml`. It must match
`authentik_ldap_bind_password`; rotate both together.

### Break-glass keys

Set `sssd_breakglass_authorized_keys` in
`inventories/homelab/group_vars/sssd.yaml`. Public keys remain unencrypted so
recovery does not depend on SOPS. An empty list leaves existing keys unchanged.

### Defaults

| Variable | Default | Purpose |
|---|---|---|
| `sssd_breakglass_user` | `breakglass` | Local recovery account |
| `sssd_breakglass_sudoers_file` | `/etc/sudoers.d/10-breakglass` | Recovery-account sudo |
| `sssd_ldap_uri` | `ldaps://ldap.home.butaco.net:636` | LDAP endpoint |
| `sssd_ldap_search_base` | `dc=ldap,dc=home,dc=butaco,dc=net` | Provider Base DN |
| `sssd_ldap_bind_dn` | `cn=ldapbind,ou=users,…` | Lookup account |
| `sssd_allowed_login_group` | `lab-linux-users` | Login group |
| `sssd_sudo_group` | `lab-linux-admins` | Sudo group |
| `sssd_sudoers_file` | `/etc/sudoers.d/60-lab-linux-admins` | Managed sudoers file |
| `sssd_offline_credentials_expiration` | `2` | Offline-login days |
| `sssd_entry_cache_timeout` | `600` | Host cache lifetime in seconds |
| `sssd_ldap_ca_cert_path` | `/etc/ssl/certs/authentik-ldap-ca.pem` | Trusted LDAP certificate |

## Operational notes

### Access and revocation

Disabling a user leaves its LDAP entry and group membership intact but changes
`ak-active` to `FALSE`. The role therefore uses `access_provider = ldap` with
an `ldap_access_filter` that requires both group membership and
`ak-active=TRUE`.

`sssd_sudo_group` does not grant login access. Administrators must also belong
to `sssd_allowed_login_group`.

### Caching

Revocation passes through two caches:

1. Authentik LDAP Outpost: measured at about 1m15s for additions and 2m22s for
   removals on `sssdtest1` (`search_mode: cached`, 2026-08-17).
2. SSSD: bounded by `sssd_entry_cache_timeout` (600s; upstream default 5400s).

The approximate revocation ceiling is their sum. `getent group` and `id` may
temporarily disagree because they use different caches; sudo follows `id`.
Run `sudo sss_cache -u <user>` for immediate host-side invalidation.

Lowering `entry_cache_timeout` does not shorten existing on-disk entries. The
role runs `sss_cache -E` after `sssd.conf` changes. Use
`sssctl user-show <user>` to inspect expiry timestamps. Authentik
`search_mode: direct` would remove the Outpost cache but make every lookup live,
so it is not used.

### Outages and recovery

`sss_cache -E` only marks entries stale; cached identities and SSH keys remain
available during an LDAP outage. Removing `/var/lib/sss/db/*.ldb` while SSSD is
stopped removes them until LDAP returns and SSSD restarts.

Offline credentials cover short outages but are not break-glass access. The
local account and its SSH keys remain the recovery path.

### Certificate rotation

The committed LDAP certificate is public data and avoids distributing an
Authentik admin token to every client. Monitor the LDAPS certificate expiry.
To rotate it:

1. Delete the `homelab-ldap` certificate in Authentik.
2. Run the Authentik playbook to regenerate it.
3. Export the new certificate into this role.
4. Run the SSSD playbook.
