# ADR-0069: Track dotfiles vendor with Renovate

- **Status:** Accepted
- **Category:** Repository & delivery
- **Date:** 2026-10-12
- **Related:** [ADR-0049](0049-manage-shared-cli-tools-with-mise.md)

## Context

Dotfiles updates its installers independently of homelab. The recorded vendor
SHA and drift check reproduce a commit but do not propose or synchronize updates.

## Decision

Track dotfiles `main` through a Renovate regex manager and `git-refs` datasource.
Keep `ref: main` as the dependency value and the full commit SHA as its digest.
A same-repository Renovate PR triggers a workflow that runs the base revision's
sync script and commits generated files to that PR branch. Only the recorded
revision and generated paths may differ from the base; upstream files are fetched
as data and never executed. Preserve the mise template checksum substitution.

Use `GITHUB_TOKEN` for the commit and explicitly dispatch vendor, shell and Packer
checks with the synchronized commit SHA as an explicit checkout input. Token
updates can leave PR workflows awaiting approval, so dispatched checks provide
validation without approval. For same-repository Renovate PRs changing only the
dotfiles REVISION, defer the installer check to synchronization; keep the
powerdns-webui check active. Notify on synchronization or subsequent validation
failure. Vendor checks always compare against the recorded SHA. Disable
automerge for this dependency.

## Consequences

SHA and generated bytes are reviewed together, including the mise config,
lockfile and kitty defaults already covered by sync. Every `main` commit can
produce an update, even if generated bytes are unchanged; path-based filtering
can be reconsidered if the noise warrants it. Synchronization and dispatched
checks require the workflows to be present on the default branch.
